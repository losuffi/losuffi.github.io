    1. 背景：Many-Lights 的 NEE 为什么难¶

    • 朴素 NEE 在成千上万光源（含十万级自发光三角面）中均匀/功率采样，命中“真正照亮当前点”的光概率极低 → 方差大、收敛慢。原文在多场景中展示了 1-SPP 噪声的严重性。
    • 核心问题：让 NEE 的选光分布 更接近真实 integrand，而非仅靠功率或均匀；同时保持可实现、可扩展。

    2. 基础：RIS 与 NEE 的位置¶

    • NEE（Next-Event Estimation）：在着色点 (P) 显式采样光与光面点 (x)，发阴影射线并估计 [ \hat{L}_d = \frac{f(x)}{p(x)},\quad f(x)=\rho,L_e,V,\cos\theta;\frac{\cos\theta_L}{d^2} ] 理想分布 (p(x)\propto f(x)) 可趋零方差。
    • RIS（Resampled Importance Sampling）：从“易采样”的源分布 (p) 生成多候选 ((X_1...X_M))，按 目标函数 (\hat{p}) 重采样为单一输出 (Y)，使样本更贴近 (\hat{p}) 对应的归一化分布 (\overline{p})。

    3. ReGIR 总览：Reservoir-Grid Importance Resampling¶

    ReGIR 把 RIS 的思想搬到 世界空间网格：先为每个体素格子预置“光样本水库”，渲染时在本地水库上做一次轻量重采样（并发阴影射线），实现 高质量 NEE。

    3.1 预处理：网格与水库¶

    • 网格：将场景包围盒划为规则 3D 网格/哈希网格（分辨率后述）。
    • 每格水库：为格子中心代表点（可记录 (P_c, N_c)）收集若干候选光样本，使用 WRS/RIS 逻辑保留 (R) 个（例如 64）样本及其统计量。
    • 基础样本来源：可用功率采样、Light Tree，或预计算的 Light Distributions（推荐，见 §4）。

    3.2 着色阶段：二次重采样¶

    • 在像素/着色点 (P) 定位网格格子 (c)；
    • 从该格水库中抽取 (S) 个样本，按更接近真实贡献的目标函数再次做 RIS，得到最终光样本；
    • 发阴影射线计算可见性并累积贡献；可与 BSDF 方向样本做 MIS 融合。

    3.3 目标函数（Target Function）设计¶

    为了让 “网格填充” 与 “着色时二次重采样” 都更像真实的 (f(x))，原文建议把几何项与可见性纳入目标函数（若成本允许）：

    [ \hat{p}(x);\propto; L_e(x);V(P_c!\leftrightarrow!x);\cos\theta;\frac{\cos\theta_L}{d^2} ]

    直觉：功率、距离与两侧余弦能把“近、朝向对、亮”的光样本权重拉高；可见性直接剔除被遮挡的候选，显著减噪。

    3.4 NEE++ / BSDF Resampling / Reuse / Bias 修正 / MIS / 去相关¶

    • NEE++：把更多“接近 (f)”的因素（可见性、几何）并入采样/重采样阶段。
    • BSDF Resampling：在重采样时把 BSDF 形状纳入 (\hat{p})（或与 BSDF-sample 做 MIS）。
    • Spatial/Temporal/Visibility Reuse：邻域/跨帧/可见性结果的复用可降噪，但会引入相关性；离线渲染通常谨慎对待时间复用。
    • Fixing the Bias：当使用近似或复用导致偏差时，需配套防御性样本（canonical reservoir）与修正策略。
    • MIS：与 BSDF-sample 合并时用 Balance/Power 权重，确保无偏与稳健性。
    • Reducing Correlations：用抖动、蓝噪序列、分层等手段抑制相关性纹理与闪烁。

    4. 改善基础样本：Light Distributions 与 Light Tree¶

    • 为何重要：若基础样本质量差（仅功率/均匀），压力会全部落在二次 RIS 与可见性测试上，方差与相关性尖刺明显。
    • Light Distributions（推荐）：为每格子预估各光贡献并保留 Top-N，构造离散分布（Alias/CDF）供 grid-fill 使用；原文报告相对“纯功率”有明显提升。
    • Light Tree / ATS 等层次结构：当构建与目标函数设计得当，质量可与上法相当甚至更优，且避免较大预计算/内存。
    • 实务上二者可混合：水库贫瘠或质量不佳时，回退到 Light Tree。

    5. 网格尺寸与内存/收益权衡¶

    • 过粗：水库分布与真实贡献偏差大，着色时难以纠正；
    • 过细：预处理时间/内存猛增，收益递减。
    • 原文在白房间、Bistro 等场景扫描发现：存在一个收益递减区间（例如尺寸从 1 降到 0.5 时收益显著，此后趋缓），需按场景特性实测选取。

    6. 实作细节：伪代码与数据结构¶

    数据结构（示意）

    struct LightSample {
  uint32 LightID;
  uint32 TriIndex;     // 发光面的话
  float2 Bary;         // 面上位置
  float  Pdf_src;      // 源分布概率（功率/LD/树）
  float  Weight;       // 累计权或目标函数值
  uint32 Seed;
};

struct Reservoir {
  LightSample Samples[R]; // R≈64
  float       Wsum;       // 权重和
  uint32      M;          // 已见候选数（用于WRS）
};

struct GridCell {
  float3 Pc; float3 Nc;
  Reservoir Rn;  // non-canonical
  Reservoir Rc;  // canonical（防御性样本）
};

    预处理（Grid-Fill）

    for (GridCell& c : Grid) {
  Reservoir Rn, Rc; init(Rn,R), init(Rc,RcN);         // e.g., R=64, RcN=12
  for (int k=0; k<CandidatesPerCell; ++k) {
    LightSample s = SampleFromBaseDistribution(c);    // 功率/LD/LightTree
    float      tp = TargetProxy(c, s);                // ~ L_e * V * cos * cosL / d^2
    WRS_Update(Rn, s, tp);                            // 非规范水库
    WRS_Update(Rc, s, s.Pdf_src>0? 1.0f : 0.0f);      // 防御性样本
  }
  Store(c, Rn, Rc);
}

    着色（NEE 阶段二次重采样 + 阴影）

    Shade(P, N, wo) {
  GridCell& c = LocateCell(P);
  Reservoir R1; init(R1, 1);
  for (int i=0; i<S; ++i) {                           // S≈2~8
    LightSample s = DrawFromReservoir(c.Rn, rng);
    float      tp = TrueTarget(P, N, s);              // 更严格评估，可含 BSDF
    WRS_Update(R1, s, tp);
  }
  LightSample y = FinalPick(R1, c.Rc);                // 与防御性样本融合
  if (ShadowVisible(P, y)) {
    return Accumulate(P, N, wo, y);                   // / pdf 等项按实现
  }
  return 0;
}

    提示：生产实现中还需要把 pdf 变换（参数域→立体角域）、MIS 与 BSDF-sample 的联合权重、可见性缓存与合批阴影射线、随机序列/分层策略 衔接完整。

    7. 调参与诊断 Checklist¶

    • 网格分辨率扫描：记录（预处理时长、内存、到达目标误差的 SPP/时间）。
    • 退化案例：白房间、小强光、狭缝/烟囱、薄壁、极小自发光片。
    • 相关性监测：空间/时间相关热图；历史网格参与比例 vs. 闪烁。
    • 能量校验：关闭 MIS 单独验证 NEE 的无偏；检查雅可比变换是否完备。
    • 可见性代价：按场景切换“目标函数是否含可见性”，评估收益/代价。
    • 基础样本来源 AB 测试：功率 vs. LD vs. Light Tree。
    • BSDF-sample 联测：与 NEE 做 MIS，核对两侧可反推概率。

    8. 常见坑¶

    1. 概率/域不一致：参数域采样却用立体角域权重，缺少雅可比 → 偏差。
    2. 几何项符号：(|\cos\theta|, |\cos\theta_L| / d^2) 处理与遮挡置零。
    3. 防御性样本占比过高：易放大相关；尽量提高基础样本质量以减少其权重。
    4. 时间复用：单帧观感改善但跨帧相关加重，离线渲染需谨慎。
    5. 预处理瓶颈：Light Distributions 若在 CPU 排序构表，易成瓶颈；应迁移 GPU。

    9. 经验参数（起步建议）¶

    • 每格水库：(R_n \approx 64)，canonical (R_c \approx 12)。
    • 着色二次样本数：(S \approx 4)（2~8 视场景与预算）。
    • 目标函数：至少含 (L_e, \cos\theta, \cos\theta_L, 1/d^2)；若预算允许，把 可见性 并入。
    • 基础样本：优先 Light Distributions 或高质量 Light Tree；功率采样仅作为保底。
    • 网格：按场景扫描找到“收益递减点”，避免盲目过细。

    10. 结论¶

    ReGIR = 世界空间网格 + 预置水库 + 着色时二次 RIS。 要让 many-lights 的 NEE 真正高效稳健，三件事最关键：

    1. 高质量基础样本（Light Distributions / Light Tree），
    2. 贴近 (f(x)) 的目标函数（几何+可见性+BSDF/MIS），
    3. 合适的网格分辨率与相关性治理（复用策略、抖动/分层、诊断工具）。

    附：关键公式与符号¶

    • 直接光积分： [ L_o(P,\omega_o)=\int_A \rho(P,\omega_o,\omega_i),L_e(x),V(P\leftrightarrow x),\cos\theta,\frac{\cos\theta_L}{d^2},dA_x ]
    • 理想采样：若 (p(x)=c,f(x))，则 (\frac{f(x)}{p(x)}=\frac{1}{c}) 为常数（零方差）。
    • ReGIR 目标函数近似（用于 grid-fill / 重采样权重）： [ \hat{p}(x)\propto L_e(x),V,\cos\theta,\frac{\cos\theta_L}{d^2} ]

    附录 A：UE/RDG 集成路线图（可直接落地）¶

    目标：把 ReGIR 替换/增强 NEE 的“选光”环节，并与 RDG 的阴影射线发射/合批流程衔接。

    资源与数据面

    • FRDGBuffer：批量阴影射线（起点、方向、tmax、payload 索引）。
    • FRDGTexture：GBuffer/法线/深度/材质 ID。
    • FReGIRGrid：网格常量缓冲 + 水库缓冲（结构体如 §6）。
    • FLightAliasTables：Light Distributions 的 alias/CDF 表。

    图谱（简化）

    1. BuildLightDistributionsPass（可离线/场景变动时触发）：评估各格子对各光的贡献，构离散分布；GPU 化排序优先。
    2. ReGIRGridFillPass：按分布采样候选并做 WRS，写入 FReGIRGrid。
    3. GatherSurfacePass：从 GBuffer 取像素的 (P,N,wo)；定位格子；为每像素抽取 (S) 个样本 → 写入 ShadowRayBuffer。
    4. TraceShadowsPass：一次性发射所有阴影射线（DXR/Work Graphs），写回可见性。
    5. LightingAccumPass：根据可见性与权重累积直接光；与 BSDF-sample MIS 融合。

    注意事项

    • MIS 时要能反推“另一路策略”的 pdf；
    • 参数域→立体角域 pdf 的雅可比；
    • 反相关/抖动策略，避免棋盘纹理；
    • 异步/流水：GridFill 与渲染分帧/双缓冲，减少卡顿。
